# Distribution guidance

Make the repository earn attention before promoting it.

- Name it after the job, using memorable and searchable words without overclaiming.
- Put the outcome, intended user, and a concrete example above the README fold.
- Show the install command early and provide a five-minute quick start.
- Include an honest comparison: what the skill does, does not do, and when another tool is better.
- Add relevant GitHub topics and structured skill metadata.
- Ship a tagged release and a small changelog so visitors see maintenance intent.
- Make issues and contributions easy, but avoid empty roadmap theatre.
- Prefer one excellent example over many generic examples.

After launch, propose promotion separately. Do not post, message, submit forms, or solicit stars unless the user explicitly authorizes that external action.
